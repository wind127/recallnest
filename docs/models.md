# 模型配置与整理任务

模型是可选能力。知巢自己保存原文、版本、知识条目、记忆状态与复习进度；连接模型后增加自动整理、对话和可选语义检索。

## 配置聊天模型

在设置中填写接口 base URL、聊天模型名称和供应商需要的密钥。base URL 应包含 API 路径，通常以 `/v1` 结尾；服务会在其后调用 `/chat/completions`。地址支持 HTTP/HTTPS，不接受 URL 内的用户名、密码、查询参数或片段。

保存配置后，可以点击测试连接。测试会向当前聊天模型发出一条简短请求；“已经配置”只表示字段完整，“连接已验证”表示这次测试成功。修改配置或重启服务会清除验证状态。

API 读取设置仅返回是否已有密钥。更新时省略密钥字段会保留原值，传入空字符串会清除；界面应将这两种操作分开。连接配置写入数据目录的 `provider-settings.json`，有尽力限制为文件所有者访问的权限，不做加密。环境变量会在下次启动时重新覆盖对应的已保存字段。

模型服务必须支持指定的结构化 JSON 输出。整理结果还会经过本地字段、数量、原文引用和角色校验；接口可连接不代表所有整理输出都能通过校验。

## 整理如何运行

导入或追加消息先保存原文，再创建持久化整理任务。首次整理覆盖全部分支的文本，长消息分段处理；后续任务使用已处理的消息版本记录，整理新增或被编辑的文本。

所有分段结果校验完成后，服务在同一个写事务中再次核对来源版本，再保存知识、卡片和记忆候选。来源已经变化的结果会丢弃，等待新版本任务。整理不会覆盖你修订过的知识或卡片。

| 任务情况 | 后续处理 |
| --- | --- |
| 未配置聊天模型 | 显示配置要求；保存有效配置后重新排队 |
| 暂时的限流、服务错误、超时或网络错误 | 有间隔地重试，最多三次 |
| 身份验证、结构或引用错误 | 保留原文，查看原因后手动重试 |
| 来源版本改变 | 旧任务标记为已被新版本替代 |
| 合成示例 | 跳过模型调用，使用明确标注的示例条目 |
| 仅会话原始记录追加，消息版本未变化 | 不重复调用模型 |

手动重试把任务重新排队；立即执行会尝试运行选中的排队任务。成功版本的处理记录会防止重试重复生成条目。已有消息的内容、角色或原始记录被编辑而产生新版本时，会重新整理该版本，以刷新证据。错误文本经过处理，不显示供应商响应原文或密钥。

## 可选嵌入模型

填写嵌入模型后，服务调用同一 base URL 下的 `/embeddings`。通过显式重建索引生成当前内容的向量，再启用语义搜索。重建后内容发生变化，需要再次重建以更新相应索引。

| 配置 | 可用检索 |
| --- | --- |
| 没有模型 | 文本匹配，支持中文与筛选 |
| 只有聊天模型 | 文本匹配、自动整理与带背景对话 |
| 增加嵌入模型并重建索引 | 文本和兼容向量融合检索 |

缺少嵌入配置或请求失败时，搜索会回退到文本并说明原因。改变内容、模型或供应商配置后，不会继续使用不匹配的旧向量。

## 对话使用什么背景

对话使用当前分支的相关消息、有效的已确认记忆和来源仍有效的相关知识。返回结果显示实际发送的上下文 ID 和证据。记忆候选、拒绝、失效和已替代的个人背景不会进入新对话；有引用的确认记忆只使用当前有效证据，全部证据过时的记忆暂不使用。

用户消息在请求模型前归档。模型失败时没有虚构的助手回答，你可以在原会话重试。客户端使用稳定的回合 ID，让网络重试复用同一条用户消息与已完成的回答。

请求按完整 UTF-8 大小控制上下文，先保留本轮完整用户消息，再选择能容纳的背景和历史。单条消息连同必要请求字段超过预算时，返回 `413 request_too_large`，原文仍然保存；缩短内容后作为新回合发送。

原文和选中的背景会发送到你配置的模型接口。选择本地或远程服务由你决定；连接密钥作为请求头使用，不进入对话提示词或归档导出。
