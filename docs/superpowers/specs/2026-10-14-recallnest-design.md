# RecallNest（知巢）首版设计提案

日期：2026-10-14。状态：用户已批准，进入实施。

## 1. 产品定位与成功标准

一个本地运行、可自部署的个人 AI 知识与记忆应用，把会话变成可回查的知识、项目记录、复习材料和不断更新的个人背景。

| 用户要求 | 首版行为 | 验收方式 |
| --- | --- | --- |
| 梳理历史会话 | 导入 ChatGPT 导出文件、Codex JSONL、统一 JSON 与 Markdown；保留原文，生成摘要、主题、问答和记忆候选 | 导入有分支和重复记录的测试资料；核对原文、数量与来源；再次导入不产生重复条目 |
| 使用中持续沉淀 | 应用内对话自动归档并创建整理任务；本地 Codex 采集器按用户配置的目录增量同步；API/MCP 接收其他工具主动提交的会话 | 新增消息后出现于知识库；重启、重放和文件追加不重复导入；失败任务能重试 |
| 方便查阅和复习 | 搜索、标签、项目筛选、时间线、原文跳转、收藏、复习卡片和到期队列 | 搜索命中并打开对应消息；按复习反馈更新下次到期时间；没有资料时显示真实空状态 |
| AI 越来越了解用户 | 提取带证据的偏好、目标、背景和状态；支持确认、纠正、拒绝和失效；后续回答加载相关已确认记忆 | 确认一条偏好后新会话引用它；拒绝或失效后不再使用；状态变化保留历史与证据 |

首版来源按已批准默认方案，Codex + ChatGPT 优先。统一格式和工具接口为后续扩展保留边界。

## 2. 三种路线与推荐

1. **独立本地应用（推荐）**：React + TypeScript 界面，Python API，SQLite 数据库。能围绕导入、复习、个人记忆设计完整流程，依赖和部署成本可控。
2. **基于大型现有应用二次开发**：能复用聊天和账户能力，但需要承担较大的代码、部署和许可证适配成本，复习与证据化记忆仍需额外实现。
3. **只做 MCP 记忆服务器**：接入 AI 工具较轻，但用户日常查阅、修订和复习体验不足。

推荐路线 1，同时提供轻量 CLI/API/MCP 接入。首版集中完成单用户本地使用，不扩展为多租户云平台。

## 4. 架构与模块边界

- **界面**：React、TypeScript、Vite。中文为首版默认语言，提供桌面与移动布局。
- **服务**：FastAPI、Pydantic、SQLite。数据库保存会话原文、结构化条目、证据、任务与复习状态；提供 JSON/Markdown 导出。
- **导入器**：各种来源转换为统一 Conversation/Message 格式；记录外部 ID、时间、角色、分支与来源信息。
- **整理服务**：生成摘要、知识问答、项目决策、待解问题、记忆候选和复习卡片。模型输出先校验，再持久化。
- **任务执行器**：持久化任务状态，处理重试和并发幂等；服务重启后恢复未完成任务。
- **检索与上下文服务**：检索原文、知识与已确认记忆；组合小规模相关上下文并保留引用。
- **接入层**：REST API、CLI、MCP，以及显式配置目录的 Codex 增量采集器。

数据流：导入或新增消息 → 保存原文 → 创建整理任务 → 提取结构化内容 → 校验证据 → 入库 → 搜索/复习/记忆确认 → 用于后续回答。

不依赖独立向量数据库或云账户。首版提供中文友好的文本检索；配置嵌入模型后增加语义检索并与文本结果合并。

## 5. 核心数据与来源追踪

- Conversation：来源、外部会话 ID、标题、时间、项目、原始记录。
- Message：外部消息 ID、角色、内容、时间、父消息与分支信息。
- KnowledgeItem：标题、摘要、正文、类型、标签、项目、整理版本。
- Evidence：知识或记忆对应的会话 ID、消息 ID、引用片段。
- Memory：类别、主题、内容、候选/已确认/拒绝/失效状态、生效时间、历史关联、证据。
- ReviewCard：问题、答案、关联知识与来源、到期时间、反馈记录。
- Project：名称、介绍、目标、状态、关联会话与知识、外部产物链接。
- Job：任务类型、来源版本、状态、尝试次数和错误分类。

导入采用来源和外部 ID 去重；无外部 ID 时采用稳定内容指纹。新增消息触发增量整理；已有消息被修改时保留旧版本，重新生成相关派生内容。

保留会话分支，界面默认展示来源标记的主分支；用户可切换分支。未知来源结构显示导入错误报告，不静默猜测。

## 6. 四项能力的具体体验

### 历史会话整理

拖入文件，先看到解析预览与导入范围，再确认导入。导入完成后显示会话数、消息数、重复数、失败数与整理任务进度。支持批量重试失败的整理任务。

ChatGPT 支持 conversations.json 与包含该文件的 ZIP；Codex 支持本地会话 JSONL。原始格式版本通过真实格式样例和合成测试固定契约，不承诺无法访问的平台数据。

### 持续沉淀

应用内新增会话、用户消息与 AI 回复自动保存。每次完成对话生成可见的整理任务与结果。

Codex 采集器仅处理用户指定的目录，记录已处理文件与消息指纹；追加记录增量导入。提供启动、停止与状态命令，首次接入能预览历史导入范围。

ChatGPT 首版以历史导出和主动提交接口接入。浏览器扩展自动采集作为后续版本，不声称首版能在网页外无配置监听所有聊天。

### 查阅与复习

提供“总览、知识库、会话、项目、复习、我的记忆”六个入口。搜索支持关键词、来源、项目、类型、标签和时间范围。

知识详情包含答案、关键点、关联项目与原文证据。复习卡片先显示问题，揭示答案后可选择“忘记、困难、记住、轻松”。到期调度使用明确的简单间隔规则并保存反馈，不宣称采用未经实现的高级算法。

提供按项目或日期生成的复习集合，支持编辑与暂停卡片。收藏和待解问题可直接进入查阅列表。

### 用户理解不断累积

记忆类型包括偏好、背景、目标、当前状态与约束。AI 提取的内容默认是候选，需要用户确认才能作为确定的个人背景参与回答。

用户可编辑、确认、拒绝、设为失效，且能看到原文出处。目标或状态变化通过“替代旧记忆”建立历史关联；旧记忆保留但不作为当前状态加载。

用户提问不自动等同于用户事实，例如“怎么用 Java”不会形成“用户熟练掌握 Java”的记忆。AI 回答中的推断不会自动写成用户事实。

“越来越了解”通过可见的记忆增长、修订历史和回答所用背景实现，不通过模型权重训练实现。

## 7. 模型与故障处理

模型可配置 OpenAI 兼容接口，包括适配的本地模型服务。服务端保存连接配置；密钥不返回到网页、不写入日志、不进入导出或 Git。

未配置模型时，导入、查阅、搜索、手动编辑记忆与复习仍可使用。模型整理和问答入口明确提示配置要求，演示资料明确标记为示例。

提取必须返回结构化结果并附存在的消息引用。校验失败、超时、限流和连接错误产生可重试任务；失败不影响原文保存，也不生成虚假的成功结果。

导入 ZIP 设置解压大小与文件数量上限；只读取支持的文件，防止路径穿越。外部 Markdown 和模型内容均按不可信文本处理。

默认服务只监听本机回环地址。首版部署范围是本地单用户，公开网络部署需要单独设计认证。

## 8. 测试与交付

关键测试：导入分支、重复导入、消息追加与修改、采集器重启、任务恢复、模型异常与无效引用、中文检索、记忆确认/失效、复习调度和导出。

浏览器验收：示例导入 → 查看知识及原文 → 确认记忆 → 新会话使用背景 → 完成一张复习卡片；另验证空数据与模型未配置状态。

交付包含可运行源码、中英文 README、MIT LICENSE、合成示例资料、配置说明、API/MCP 接入文档、测试、GitHub Actions 和 Docker 部署文件。

GitHub 发布目标暂定为已连接账户 wind127 下的公开 recallnest 仓库。发布内容为源码、文档与合成示例，运行产生的对话、个人画像、数据库与密钥由忽略规则隔离。

实现通过测试与浏览器验收后，再创建仓库、推送并核实远端提交。已获得用户发布授权；如果缺少账户能力，再处理具体登录或访问条件。

## 10. 自查结论

四项用户要求均有对应功能和验收标准。持续沉淀明确覆盖应用内对话、Codex 指定目录和主动提交接口；ChatGPT 网页自动采集没有伪装成已具备能力。复习、记忆治理、中文检索和失败恢复均纳入首版。

用户已批准本方案。开发与验证完成后发布源码，个人运行数据不进入仓库。
